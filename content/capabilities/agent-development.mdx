## 我的理解

Agent 的价值不只在“能聊天”，而在于它能否在明确权限内读取可靠上下文、调用工具、留下可检查的中间结果，并用测试或人工复核闭环。提示词可以约束行为，但安全边界必须落在代码和数据权限上。

## 做过的事

- 长期把编码 Agent 用在需求澄清、规格拆分、代码实现、测试和审查中，并持续调整给 Agent 的项目文档。
- 为这个 blog-template 设计了基于公开资料的检索问答、站内引用、未知问题拒答和服务端模型适配层。
- 参与过某 MaaS 平台相关工程实践；这里只保留无法反查具体单位的公开概括。

## 边界与失败

目前的完整实践集中在个人与团队开发工作流，尚未证明自己能独立承担大规模 Agent 产品的长期评测、成本治理和生产可靠性。Agent 输出偶尔会自信地偏离事实，因此我不会把“生成成功”当作“任务完成”。

## 下一步

建立更系统的任务评测集，继续研究上下文压缩、工具权限、可观测性与失败恢复，让 Agent 的效率提升可以被复现和衡量。
