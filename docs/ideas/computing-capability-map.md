# 计算机能力地图

> 状态：方案已批准，等待实施计划审批
> 日期：2026-08-01

## Problem Statement

如何让任何访客在短时间内理解站主跨计算机领域的真实能力、实践证据和成长方向，同时避免传统技能百分比的虚假精确感，并且不公开姓名、学校、实习单位或私人联系方式？

## Recommended Direction

建设“能力地图 + 实践档案”：首页只展示当前重点方向，完整内容进入 `/capabilities`。信息结构采用证据型档案，视觉上延续纸张、终端与轻量“思维卡片”气质，不复制任何游戏界面。

每个领域固定回答六个问题：当前处于什么阶段、如何理解该领域、做过什么、踩过什么坑、有哪些相关作品、下一步准备做什么。能力等级使用文字状态，不使用百分比或雷达图：

1. 正在了解
2. 做过练习
3. 做过完整实践
4. 能独立承担

首版领域：

- 超算与 AI Infra
- Agent 开发
- 网络安全
- 体系结构与操作系统
- 电子基础与嵌入式
- 算法与数据结构

作品分为两层：

- 精选作品：校园开源镜像站、开源自学文档、blog-template。
- 实践档案：超算与 AlphaFold 优化尝试、Docker 大数据集群、FPGA 智能小车、数字逻辑实验辅助、开放数据提取工具。

## Key Assumptions to Validate

- [ ] 访客能理解四级文字状态，并认为它比主观百分比更可信；通过用户审阅和可用性检查验证。
- [ ] 六个领域足以表达当前能力边界，不需要首版引入更复杂的树状分类；通过内容填充后的重复项检查验证。
- [ ] 匿名化文案在不出现真实身份信息时仍保留足够证据；通过逐项来源核对和发布前隐私审查验证。
- [ ] GitHub 账号与仓库当前可能暴露真实身份，因此首版不直接提供相关外链；只有完成公开资料审计并再次获批后才启用。

## MVP Scope

- `/capabilities` 能力地图页面与六个领域的仓库内内容文件。
- 首页展示三个重点领域并链接到完整能力页。
- 三个匿名化精选作品替换现有示例作品。
- 作品允许不提供外部链接，以满足匿名发布要求。
- 能力资料作为公开授权来源供阿竹检索；资料不足或被问及隐藏身份时继续拒绝猜测。
- 手机、平板和桌面响应式布局，键盘可访问，尊重减少动画设置。

## Privacy Contract

- 公开身份只使用 `zhujiechong`；它是站点笔名，不代表真实姓名。
- 不公开真实姓名、学校、学院、实习单位、电话、私人邮箱和可定位的服务器信息。
- 竞赛名称、年份、赛制和已确认名次可以公开：2024 IndySCC 线上赛第三名、2025 ASC 二等奖；不公开参赛学校、队名或队员身份。
- 实习只写“某 MaaS 平台”。
- 学校相关经历统一写作“校园”“校内团队”或“校内开源社团”。
- 网络安全故事不得包含服务器地址、账号、漏洞入口或仍可利用的攻击细节。
- fork 和上游项目只能标记为研究尝试，不得写成原创作品。

## Not Doing

- 百分比技能条与雷达图——缺乏可验证尺度。
- 自动从 GitHub 同步技能或作品——会扩大隐私风险并引入不稳定外部依赖。
- 完整技能关系图——首版信息量不足以支撑复杂交互。
- 复制《极乐迪斯科》界面——影响原创性、可访问性与维护性。
- 发布真实机构和身份线索——与已确认的匿名边界冲突。
- 把失败尝试包装成成功优化——削弱可信度。
